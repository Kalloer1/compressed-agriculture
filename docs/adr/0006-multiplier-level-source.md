# 0006 · 倍率的 L 取自作物正下方的压缩方块

- 状态：已采纳（2026-10-31）
- 影响面：§9 统一写入入口第 2 步

## 背景

方案 v1.9.2 §9 只写了一句 `每种物品 × 9^L`，从未定义 `L` 从哪来。§4 说 BE 不持久化 `level`（从 Block 读取），§2 说 18 个方块承载等级，但两处都没把「某次结算用哪个方块的等级」连起来。

## 决策

`L` = **该次结算所对应作物的正下方那个压缩方块的等级**。

若作物正下方不是压缩方块，则该次结算不走本模组路径（无货仓可写，不构成结算）。

## 理由

- 这是唯一不需要额外状态的定义：等级本来就编码在「脚下那块地」的 Block 里，读到就是。
- 与 §6.2 树苗路径、§7.2 瓜类路径的物理结构一致——三者都是「产物归属到脚下那块压缩方块」。
- 若改用 `chestCount` 或其他来源推导 L，会让 ADR-0003 确立的正交性失效。

## 需要注意的边界

- **作物不必长在压缩耕地上**。玩家在普通泥土/耕地上种的东西不进入本系统。所以「方块属于 compressible_crops 标签」不等于「会走压缩结算」，还要求脚下是压缩方块。
- 2×2 巨树：四格树苗可能站在**不同等级**的压缩方块上。此时 L 取自 ADR-0004 选中的那个 BE 所在方块的等级——容器选择与等级来源是同一格，不分离。
- 瓜类：L 取自茎下方的压缩耕地的等级（§7.2 已要求茎下方是压缩耕地）。
- 若作物脚下是压缩泥土（非耕地），原版本就不允许种植，走不到结算。

## 后果

- `settle(...)` 的签名需要显式接收 `L`（由调用方从脚下方块读出后传入），入口内部不再反查坐标。
- 这样统一入口保持纯函数：不读世界、不查 Block、只做「乘倍率 + 写货仓 + 原子性判断」，与 §9「入口本身不包含任何方块 ID 判断」的要求一致。
