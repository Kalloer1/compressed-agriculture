# 0007 · 空掉落清单记录 WARN 而非 DEBUG

- 状态：已采纳（2026-10-31）
- 影响面：§5.6 失败语义、§11.7 统一写入入口

## 背景

方案 v1.9.2 §5.6：

> `INVALID_INPUT`（掉落清单为空）：不写入、不重置，避免破坏空战利品表植株。

§6.3 对通用回退另有「记录一次调试日志」。§5.6 对 `INVALID_INPUT` 未规定日志级别。

## 决策

`settle` 返回 `INVALID_INPUT` 时记录 **WARN**，内容包含方块 ID、维度、坐标、以及作物当前 `BlockState`。

## 理由

- 「掉落清单为空」在实践中**几乎总是错误**：整合包改了战利品表、KubeJS 脚本写错、模组作物没注册掉落。这不是正常状态，DEBUG 级别会让玩家在正式游戏里完全看不到线索，只能看到「这块地永远收不了」。
- 后果是**永久卡住**（作物保持成熟、永远结算失败，见 ADR-0005 同样保留状态）。永久性问题必须可诊断。
- WARN 有频率风险，但触发条件是「某个方块位置每次都结算失败」，且正常整合包里不会发生。真发生刷屏本身也是有效信号。

## 后果

- 需要按 `(Dimension, BlockPos)` 做限流：同一位置每 600 tick（30 秒）最多记一次，避免恶意/误配整合包刷爆日志。
- 限流表与 ADR-0001 的待观察集合分开维护，不要复用（生命周期不同）。
- 玩家可见反馈不进 WARN 通道——日志是给整合包作者看的，玩家该看到的是 GUI 里该格显示「未知产物」之类的提示。
