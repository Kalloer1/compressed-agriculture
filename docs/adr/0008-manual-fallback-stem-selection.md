# 0008 · 手动右键兜底按北东南西取第一个匹配茎

- 状态：已采纳（2026-10-31）
- 影响面：§7.5 手动右键兜底

## 背景

方案 v1.9.2 §7.5：

> 从结果方块四邻域按北、东、南、西顺序找匹配的茎（`StemBlock` 或标签茎），且茎下方为压缩耕地；

顺序已经写了，但没说「找到多个怎么办」。一格结果方块的邻域里理论上可以出现两个都指向它的茎：两个相邻茎各自成熟后，`StemBlock` 只会把果实放在自己正前方，实际很难重合，但**模组茎、被活塞推动的结果方块、两个不同茎同时满足条件**都能构造出这种情况。

## 决策

按北 → 东 → 南 → 西遍历，**取第一个匹配的茎**，立即使用，不再继续找。

## 理由

- 与 ADR-0004 同一思路：固定遍历序、取首个，结果可预测且可复现。有歧义时不做额外计算。
- 「取最近的」需要算欧氏距离，但四邻域规则下两个候选到结果方块的坐标距离完全相同（都是 1 格），无法区分，规则退化。
- 「按果实匹配度过滤」需要比对 `fruit` 字段，能区分不同种的茎，但对**同种茎**仍无解，且引入不必要的复杂度。

## 后果

- 同一结果方块被右键时，产物归属始终是北侧那个茎所指的货仓。
- 若第一个匹配的茎下方不是压缩耕地，**不跳过、不继续找**——直接判定该结果方块不走压缩路径，放行原版。理由：顺序须固定，不能变成「找到能用的为止」的可变规则。
- 该行为与 §7.5 第 2 条「茎下方为压缩耕地」的筛选条件叠加时，实际含义是「北→东→南→西中第一个匹配的茎，同时检查其下方是否压缩耕地」。
