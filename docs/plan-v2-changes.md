## A 级 · 不修会编译失败或功能死掉

### A1 · `BlockTags.CROP` → `BlockTags.CROPS`（ADR-0009）

| 位置 | 原文 | 改为 |
|---|---|---|
| §0 表格 | `BlockTags.CROP` 标签 | `BlockTags.CROPS` 标签 |
| §1.1 | 默认引用 `#minecraft:crop`；使用 `BlockTags.CROP` | 默认引用 `#minecraft:crops`；使用 `BlockTags.CROPS` |
| §5.1 | `#minecraft:crop` | `#minecraft:crops` |
| §12 最后第 1 条 | 「`BlockTags.CROP` 为单数常量名。」 | **整条删除** |

事实：`BlockTags.java:94` 是 `public static final TagKey<Block> CROPS = create("crops")`。数据文件 `data/minecraft/tags/block/crops.json`。

### A2 · 普通作物识别排除瓜类茎（ADR-0009）

§5.1「识别」在现有两条排除（树苗、可可豆）之后追加：

> 3. 方块 `instanceof StemBlock` 时一律不走普通作物路径，交由 §7 处理。

原因：`#minecraft:crops` 含 `melon_stem`、`pumpkin_stem`；而 `StemBlock extends BushBlock`、不是 `CropBlock`，会掉进 §5.2 的 AGE 回退分支，AGE 最大 7 被判成熟，与 §7 抢同一方块。

### A3 · 压缩耕地加入 `#minecraft:dirt`（ADR-0010）

§11.3「注册标签」补充第 5 项：

> `#minecraft:dirt`：9 个等级的压缩方块全部加入。

§1 末尾增加一小节「1.6 原版标签加入」，列出此项并说明理由。

原因：`StemBlock.randomTick` 放置果实前有硬检查 `below.is(Blocks.FARMLAND) || below.is(BlockTags.DIRT)`。压缩耕地不满足 → 走不到放置分支 → §7.2 的 Mixin 注入点不存在。

⚠ 同时确认：`HoeItem.TILLABLES` 是硬编码方块表、不读标签，所以加入 `#dirt` **不会**让锄头把压缩泥土变成普通耕地。但反过来意味着「锄头 → 压缩耕地」需自己实现。

### A4 · 骨粉路径改用 tick 末尾观察（ADR-0001）

§5.4 的「路径 B」整段重写。

原文明说「不取消 `BonemealEvent`……在事件返回之后，同一监听器中立即检查」——**这个「之后」不存在**。`BonemealEvent` 无 Post 变体，且触发点就在 `performBonemeal` 之前。伪代码里的 `getBlockState(pos)` 读到催熟前状态，`isMatureCrop(after)` 恒 false。

改为：

> **路径 B：骨粉催熟 → tick 末尾检测**
>
> `BonemealEvent` 监听器**不取消、不调 `setSuccessful`**，只把 `(维度, 坐标)` 记入本 tick 待观察集合，让原版完整执行 `performBonemeal`。随后在 `ServerTickEvent.Post` 遍历 `server.getAllLevels()`，对每个待观察位置读当前 `BlockState`：
> - 已成熟 → 调统一入口结算；
> - 未成熟 → 不动（原「路径 C」）；
> - 已不是作物 → 不动。
> 每 tick 无条件清空集合。

注意三点（ADR-0001 已验证）：
- `ServerTickEvent.Post` 只携带 `MinecraftServer`，不携带 Level，须用 `getAllLevels()` 遍历。
- 集合键用 `ResourceKey<Level>` + `BlockPos.asLong()`，不要用 `ServerLevel` 引用。
- `BonemealEvent` 客户端**也**触发，监听器开头必须挡掉非 `ServerLevel`。

§12 中「**骨粉催熟不触发 `CropGrowEvent.Post`**」这条保留，但删掉伪代码里「依赖事件线程模型」的注释。

## B 级 · 语义矛盾

### B1 · 货仓满不重置幼苗（ADR-0005）

§5.6 第二条改为：

| 失败 | 原文 | 改为 |
|---|---|---|
| `INSUFFICIENT_SPACE` | 不写入，不生成 `ItemEntity`，整体丢弃并**重置幼苗** | 不写入、不生成 `ItemEntity`、**保留成熟态**。下次有事件驱动时重试 |
| `INVALID_INPUT` | 不写入、不重置 | 不变，但日志级别为 `WARN`（见 B6） |

补充重试时机（三处，均不轮询）：
1. 玩家关闭该 BE 的 GUI（`PlayerContainerEvent.Close`，对本模组 menu 上方 3×3 尝试一次）
2. 玩家右键该压缩方块
3. 玩家破坏该压缩方块前（`playerWillDestroy`）

已验证前提：`CropBlock.isRandomlyTicking` 返回 `!isMaxAge`，成熟作物不再随机刻，所以保留成熟态**不会** tick 风暴。

⚠ 本模组 GUI 必须继承 `AbstractContainerMenu` 才能收到 `PlayerContainerEvent.Close`。

### B2 · 定义倍率中的 L（ADR-0006）

§9「统一写入入口」第 2 步前增加：

> **L = 该次结算所对应作物的正下方那个压缩方块的等级。**
> 若正下方不是压缩方块，则该作物不走本模组路径。
> 2×2 巨树与瓜类茎，L 取自 ADR-0004 选中的那个 BE 所在方块的等级（容器选择与等级来源同一格）。

§9 末尾补充：`settle(...)` 显式接收 `L`，入口内部不反查坐标——保持纯函数，符合「入口本身不包含任何方块 ID 判断」。

### B3 · 2×2 容器选择顺序定为一种（ADR-0004）

§6.2 第 5 条，删掉「或保持原方案的锚点 → 东 → 南 → 东南」，只保留：

> 从西北角 BE 开始，按**西北 → 东北 → 西南 → 东南**选择第一个 BE。

⚠ §6.2 第 2 条的表述也要修正。`TreeGrower.growTree` 的实际遍历是 `x: 0 → -1`、`z: 0 → -1`，即**相对 `pos` 从自身向负 X / 负 Z 扩展**，四格中任意一格都可以当锚点。原文「东南 → 东北 → 西南 → 西北，只尝试第一个找到的」语义正确但易误读，建议改为：

> 原版从事件坐标自身开始，按 `(0,0) → (0,-1) → (-1,0) → (-1,-1)` 偏移顺序搜索 2×2 方格，只尝试第一个找到的。

### B4 · 废弃 `tree_loot`，改为真实生成（ADR-0011）

- §0 表格「树苗」行：掉落来源改为「真实生成树 → 逐方块 `getDrops`」
- §1.5「树木产物映射」：**整节删除**
- §6.3「产物获取」：**整节重写**

> 1. 在原位正常调用原版 `growTree`；
> 2. 记录本次生长实际放置的方块；
> 3. 逐方块 `state.getDrops(...)` 取真实掉落；
> 4. 汇总送入统一入口，`× 9^L`；
> 5. 拆掉整棵树（含包围盒清理）。

- §11.9c「`tree_loot` JSON + 通用回退」：**删除**
- §12 最后一条「模组树苗无 `tree_loot` 映射时通用回退为树苗自身 + 木棍」：**删除**

⚠ 留白：记录「这次生长放了哪些方块」的挂钩点，实现阶段确认。

### B5 · 蘑菇模块补上骨粉催树（ADR-0013）

§8 整节重写为两条路径：

> **路径一（主要收益）：骨粉催蘑菇树**
> 1. 玩家对压缩草地上的蘑菇使用骨粉；
> 2. 不做拦截，让原版 `performBonemeal` 正常执行 `growMushroom`；
> 3. 蘑菇树生成完成后，按 §6.3 同一套「记录方块 → 逐方块取掉落 → 拆除」逻辑结算；
> 4. `× 9^L` 写入容器。
>
> **路径二（种子来源）：随机扩散，仅保留原版约束**
> 光照 < 13（除非下方是菌丝/灰化土/菌岩）、9×9×3 内同种 < 5 朵。不加速。
>
> **手动收获**：破坏蘑菇时若下方是压缩草地，写入容器。

§11.12 任务描述同步扩展。

已验证事实：
- 蘑菇树由 `mushroom_stem` + `red/brown_mushroom_block` 组成，红菇顶盖 5×5（`foliage_radius` 2），褐菇 7×7（半径 3），树高 `nextInt(3)+4` = 4–6，1/12 概率翻倍到 8–12。
- 蘑菇方块**默认不掉自身**，普通破坏掉 `red/brown_mushroom` × 0–2。所以拆一棵蘑菇树 ≈ 几十个蘑菇物品。
- `BushBlock.mayPlaceOn` 是 `is(BlockTags.DIRT) || is(Blocks.FARMLAND)` → 靠 A3 的 `#dirt` 天然满足，蘑菇可种在压缩草地上。
- `MUSHROOM_GROW_BLOCK` 只含菌丝/灰化土/`crimson_nylium`/`warped_nylium`，压缩草地**不在内** → 压缩草地上的蘑菇仍受光照 < 13 约束。不把压缩草地加进去（它是草不是菌）。

### B6 · `INVALID_INPUT` 用 WARN（ADR-0007）

§5.6 `INVALID_INPUT` 一行补充：

> 记录 `WARN`，内容含方块 ID、维度、坐标、当前 `BlockState`。按 `(维度, 坐标)` 限流，同一位置每 600 tick 最多一次。

理由：空掉落清单几乎总是整合包配错，且后果是永久卡住，必须可诊断。

### B7 · 2×2 兜底取第一个匹配茎（ADR-0008）

§7.5 第 1 条补充：

> 按北 → 东 → 南 → 西遍历，**取第一个匹配的茎立即使用**。若该茎下方不是压缩耕地，**不跳过、不继续找**，直接判定不走压缩路径，放行原版。

### B8 · 形态转换保留货仓（ADR-0002）

§2 或 §11.14 增加：

> 形态转换时货仓内容原样带到新方块，包括 `chestCount`。
> 活塞迁移（§11.13）与形态转换必须共用同一套 BE 搬运代码。

### B9 · 等级与扩容正交（ADR-0003）

§3 或 §4 增加一句：

> 等级 L 控制「进来多少」（`9^L`），`chestCount` 控制「装得下多少」（`64 × (1 + chestCount)`）。两者独立：升等级不自动扩容，扩容不改变倍率。

§4 的 `stackLimit` 计算注明必须用 `long`（`chestCount` 接近 10 亿时 `64 × (1 + chestCount)` 会溢 `int`）。

## C 级 · 你刚确认的新决策（原文完全没有）

### C1 · 树苗保留两阶段（ADR-0014）

§6.2 增加：

> 压缩树苗与原版完全一致地走 `STAGE 0 → 1 → growTree`，不跳过、不加速。

### C2 · 拆树后四格回填树苗（ADR-0014）

§6.2 第 6 条整条重写：

> 原文：成功 → DENY 原版巨树生成 → 调用统一入口结算 → 重置四格树苗 `stage=0`
>
> 改为：**允许**原版生长 → 记录方块 → 取掉落 → **拆树** → 结算 → **四格全部回填同种树苗 `STAGE = 0`**

单格树：在原位回填一棵同种树苗，`STAGE = 0`。

⚠ 三个保护：
- 回填必须在拆树**之后**，否则回填的树苗会被拆树逻辑误删。
- 原位已被其他方块占据时**不回填、不覆盖**。
- 回填的树苗会立即被识别为下一轮目标——预期行为，但要确保回填动作本身不触发结算。

### C3 · 蘑菇树拆完回填一个蘑菇（ADR-0015）

§8 增加：

> 拆完蘑菇树后，在**原蘑菇位置**回填一个同种蘑菇（用被催熟的那个 `BlockState.getBlock()`，不查 ID）。
> 原位被占据时不回填、不覆盖。

| 行为 | 结论 |
|---|---|
| 锄头转耕地 | **不会发生**（`HoeItem.TILLABLES` 硬编码，已验证）。但「锄头 → 压缩耕地」需自己实现 |
| 草蔓延覆盖压缩泥土 | 待确认：接受 or 挡掉 |
| 花/树苗可种其上 | 待确认 |
| 僵尸踩踏 / 水冲 | 待确认 |
| 蘑菇可放置 | 一致，无冲突 |

### D3 · §12 风险清单增删

**删除**：
- 「`BlockTags.CROP` 为单数常量名」
- 「模组树苗无 `tree_loot` 映射时通用回退为树苗自身 + 木棍」

**新增**：
- `BlockTags.CROPS` 是复数；`#minecraft:crops` 含瓜类茎，需在代码层排除。
- 压缩方块必须加入 `#minecraft:dirt`，否则瓜类与蘑菇路径不成立。
- `BonemealEvent` 无 Post 变体且早于 `performBonemeal`；骨粉路径必须在 tick 末尾观察。
- `L=9` 时 `9^9 = 387,420,489`，`N × 9^9` 可能逼近 `MAX_CHEST_COUNT`（`1e9`），必须 `Math.multiplyExact` 并捕获溢出。
- 真实生成树/蘑菇树后必须彻底拆除包围盒，否则残块会掉落成独立方块。
