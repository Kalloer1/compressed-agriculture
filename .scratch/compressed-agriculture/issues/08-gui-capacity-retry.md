# 08: GUI、扩容与重试时机

**What to build:** 玩家右键压缩方块打开一个 27 格的货仓界面，能看到每格存了什么、存了多少，能把东西取出来。玩家还能用配方把货仓容量升一档，让每格上限从 64 变成 128、192……没扩容的方块打不开界面但收获照常生效。货仓满了之后，玩家关界面、右键方块、或拆掉方块之前，系统都会再试一次结算。

**Blocked by:** 03（方块与货仓）、04（作物模块，提供「失败后保留成熟态」的场景）

**Status:** ready-for-agent

## 验收标准

### 界面

- [ ] 右键 `chestCount > 0` 的压缩方块打开 27 格货仓界面
- [ ] `chestCount == 0` 时**打不开界面**，但收获仍正常写入、每格上限 64
- [ ] 每格显示物品图标与 `long` 计数
- [ ] 玩家能把物品取出来到自己的背包
- [ ] 界面同时显示**等级 `L`** 与**容量档位 `chestCount`** 两个数（ADR-0003 要求界面上能判断该扩哪个）
- [ ] 服务端 / 客户端同步走标准 `CustomPacketPayload`，不做特殊优化
- [ ] menu **继承 `AbstractContainerMenu`**（否则收不到 `PlayerContainerEvent.Close`，重试路径 1 就丢了）

### 扩容

- [ ] 扩容配方：`chestCount + 1`，仅当 `chestCount < MAX_CHEST_COUNT` 时可合成
- [ ] 扩容后每格上限变为 `64 × (1 + chestCount)`
- [ ] 扩容**不改变**倍率 `9^L`，等级**不改变** `chestCount`（ADR-0003，两者正交）
- [ ] `MAX_CHEST_COUNT = 1_000_000_000L`，加载时 clamp

### 三处重试时机（ADR-0005，均不轮询）

- [ ] 玩家关闭本模组 menu → 挂 `PlayerContainerEvent.Close`，对该 BE 上方 3×3 范围尝试一次结算
- [ ] 玩家右键该压缩方块 → 交互时顺带尝试一次
- [ ] 玩家破坏该压缩方块前 → `playerWillDestroy` 里尝试一次
- [ ] 三处共用同一套重试逻辑，普通作物与瓜类**不各写一份**

### 货仓数据

- [ ] GUI 的读写不破坏 03 定下的序列化约束（无 `cropId`、`counts[i] == 0` 时 `slotItems[i] == null`）

## 备注

- 重试的验收场景：把货仓填满 → 作物长熟保持成熟态 → 打开界面取走一些 → 关闭界面 → 作物应被补收并重置幼苗
- GUI 渲染本身无自动化测试价值（spec Seam 3），靠手动验证
- 扩容配方放这里而不是 03，因为它是唯一能看见 `chestCount` 数值的地方
