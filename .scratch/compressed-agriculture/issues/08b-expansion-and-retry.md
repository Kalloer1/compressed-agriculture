# 08b: 扩容配方与三处重试时机

**What to build:** 玩家能用配方把货仓容量升一档（每格上限 64 → 128 → 192 …）。货仓满了导致结算失败时，玩家关界面、右键方块、或拆掉方块之前，系统都会再试一次结算，让成熟作物被补收。

**Blocked by:** 08（界面已能读写货仓）、04（作物模块）、07（瓜类模块）

**Status:** ready-for-agent

## 验收标准

### 扩容配方

- [ ] 扩容配方：`chestCount + 1`，**仅当 `chestCount < MAX_CHEST_COUNT` 时可合成**（到顶时配方不匹配，不消耗材料）
- [ ] 输入 = 1 个压缩方块 + 其余材料（材料自定，写进票内）；产物保留输入方块的**等级、形态与全部 27 格内容**，只把 `chestCount` 加 1
- [ ] 累加用 `Math.addExact`；结果超 `ChestCapacity.MAX_CHEST_COUNT` → 不匹配
- [ ] 扩容**不改变**倍率 `9^L`；等级**不改变** `chestCount`（ADR-0003，两者正交）
- [ ] `MAX_CHEST_COUNT = 1_000_000_000L`，加载时 clamp（03 已实现，确认即可）
- [ ] 实现方式：`CustomRecipe` 子类 + `RecipeSerializer` 注册，参照 `recipe/CompressedUpgradeRecipe` 的写法

### 三处重试时机（ADR-0005，均不轮询）

- [ ] **重试逻辑抽成公开入口**：现在 `CropModule.trySettle` 是 `private`。把它（以及瓜类的等价逻辑）抽成一个可复用的单元，三处重试与两个模块共用，**不各写一份**
- [ ] 位置 1：玩家关闭本模组 menu → `PlayerContainerEvent.Close`，对该 BE 上方 3×3 范围尝试一次结算
- [ ] 位置 2：玩家右键该压缩方块 → 交互时顺带尝试一次
- [ ] 位置 3：玩家破坏该压缩方块前 → 尝试一次（`PlayerInteractEvent.LeftClickBlock` 或 `BlockEvent.BreakEvent`，选一个并写明理由）
- [ ] 三处都**不做定时轮询**
- [ ] 重试只处理「成熟且尚未结算」的方块，已结算过的不重复结算（`SUCCESS` 后作物已被重置，天然满足；但要在票里写明确认过）

### 验收场景（写进票内，手工验证）

1. 货仓填满 → 作物长熟 → 保持成熟态（不重置）
2. 打开界面取走一些 → 关闭界面 → 作物被补收、重置幼苗
3. 右键该方块 → 同样补收
4. 拆掉该方块前 → 先补收，再掉出携带数据的物品（ADR-0019）

## 备注

- 三处重试都在「玩家主动动作」上，不引入 tick 轮询（ADR-0005 / ADR-0012）
- 破坏前重试与 03b 的掉落搬运是两件事、同一路径上：**先重试结算（可能写入新产出），再掉出携带数据的物品**
- 扩容配方放这里而不是 03，因为它是唯一能看见 `chestCount` 数值的地方
